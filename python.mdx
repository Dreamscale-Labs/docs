Call a model on a cloud GPU from your own robot, simulator or pipeline. No GPU
or robot needed to try it.

## What you need

- Python 3.11 or newer, in a project (`uv init` makes one).
- A Dreamscale account. Sign in once with `uv run dreamscale login`, or set
  `DREAMSCALE_API_KEY` to a key from
  [Settings → API keys](https://app.dreamscalelabs.com/dashboard/settings#api-keys).

## Install

```bash
uv add dreamscale
```

`uv run python -c "import dreamscale; print(dreamscale.__version__)"` prints
`{{sdkVersion}}` or newer.

## Get one action chunk

This runs as-is, with blank frames and zero joints:

```python
import numpy as np

import dreamscale

policy = dreamscale.connect("pi05-so101")
frame = np.zeros((480, 640, 3), dtype=np.uint8)  # H×W×3 uint8 RGB
observation = dreamscale.so101.observe(
    side_frame=frame,
    wrist_frame=frame,
    joint_positions=[0.0] * 6,  # degrees; gripper 0–100
)
chunk = policy.predict(observation, instruction="pick up the red block")
print(len(chunk.actions), "x", len(chunk.actions[0]))
```

It prints `30 x 6`: 30 actions of 6 absolute joint targets. `connect` returns
when a GPU is ready; if every GPU is busy, it waits in a queue and shows your
position. Now replace the frames and joints with your camera frames and joint
readings. See [Models](/models) for each robot's observation and actions.

## Drive a robot

<Warning>
  The robot will move. Enforce joint, speed and workspace limits locally, and
  keep a physical e-stop within reach. Cloud inference does not replace your
  robot's safety controller.
</Warning>

Call `next_action` once per control tick. It returns one action on the model's
clock, so the loop needs no timing code.

```python
import dreamscale

policy = dreamscale.connect("pi05-so101")
while True:
    action = policy.next_action(read_observation(), instruction="pick up the red block")
    robot.send(action)
```

Pass a new instruction at any time to switch tasks.

## What the SDK handles

The SDK checks each observation before sending it and names the field that is
wrong. It prepares images, streams to the GPU over the fastest path your network
allows, and blends chunks so motion stays smooth. If the connection drops, it
reconnects and holds the robot still until actions arrive. It releases the GPU
after a minute without calls and reconnects on the next one. Sessions close
when your program exits, or call `policy.close()`. In async code, use
`await dreamscale.aconnect(...)`.
