The Python SDK gives you full control of your robot, cameras and control loop.
To just run a model on an SO-101 or bimanual YAM, the CLI does it in one command:
see [SO-101](/robots/so101) or [Bimanual YAM](/robots/yam).

## What you need

- Python 3.11 or newer, in a project (`uv init` makes one).
- A Dreamscale account. Sign in once with `uv run dreamscale login`, or set
  `DREAMSCALE_API_KEY` to a key from
  [Settings → API keys](https://app.dreamscalelabs.com/dashboard/settings#api-keys).

## Install

```bash
uv add dreamscale
```

`uv run python -c "import dreamscale; print(dreamscale.__version__)"` prints
`{{sdkVersion}}` or newer.

## Shared models and your deployments

- **A shared model** runs one robot type with fixed inputs and outputs, listed
  on [Models](/models): `dreamscale.connect("pi0.5-bimanualyam")`.
- **Your deployment** is your fine-tune, shaped to your robot:
  `dreamscale.connect("acme-robotics/towel-fold")`. See
  [Deployments](/deployments).

Both return a policy with `predict` and `next_action`.

## LIBERO quick start

This runs as-is, with no robot. It sends blank frames to `pi0.5-libero`, the
π0.5 model for the LIBERO simulator:

```python
import numpy as np

import dreamscale

policy = dreamscale.connect("pi0.5-libero")
frame = np.zeros((256, 256, 3), dtype=np.uint8)  # H×W×3 uint8 RGB
observation = dreamscale.libero.observation(
    agent_frame=frame,
    wrist_frame=frame,
    state=[0.0] * 8,
)
chunk = policy.predict(observation, instruction="pick up the black bowl")
print(len(chunk.actions), "x", len(chunk.actions[0]))
```

It prints `20 x 7`: 20 actions of 7 values. If every server is busy, `connect`
waits in a queue and shows your position.

## Working with any robot

<Warning>
  The robot will move. Enforce joint, speed and workspace limits locally, and
  keep a physical e-stop within reach. Cloud inference does not replace your
  robot's safety controller.
</Warning>

Your code reads and commands the robot. The robot's observation helper packages
what you read, and the SDK checks it before sending. Call `next_action` once per
control tick. This drives an SO-101:

```python
import dreamscale

policy = dreamscale.connect("pi0.5-so101")

def read_observation():
    # Your robot's code: read the frames and state.
    side, wrist = ..., ...  # H×W×3 uint8 RGB frames
    joints = ...  # 6 values: LeRobot degrees, gripper 0–100
    return dreamscale.so101.observation(
        side_frame=side, wrist_frame=wrist, joint_positions=joints,
    )

def send_to_robot(action):
    # Your robot's code: apply the 6 absolute joint targets (same order and units).
    ...

while True:
    send_to_robot(policy.next_action(read_observation(), instruction="pick up the red block"))
```

Other robots use their helper from [Models](/models); a deployment's dashboard
page has its loop. Pass a new instruction to switch tasks.

## What the SDK handles

The SDK checks each observation and names any wrong field. It prepares images,
picks the fastest network path, and blends chunks so motion stays smooth. If the
connection drops, it reconnects and holds the robot still. It frees the server after
a minute idle and reconnects on the next call. Sessions close when your program
exits, or with `policy.close()`. In async code, use `await dreamscale.aconnect(...)`.
