Training fine-tunes π0.5, FLUX.3 Action, GR00T N1.7 or Praxis-1 on your robot's demos, on our GPUs. Upload your dataset
once, train on it, and turn the result into a [deployment](/deployments) you can run.

## What you need

- The latest CLI: `uv tool upgrade dreamscale`.
- Credits on your account: you see the price and approve it before anything starts.
- A LeRobot dataset (v2.x or v3.0), in a local folder or on Hugging Face.

## 1. Upload your dataset

```bash
dreamscale datasets upload ./towel-fold
```

A dataset on Hugging Face can skip this, or be copied in with
`dreamscale datasets import hf://your-org/towel-fold`. See [Datasets](/datasets).

## 2. Train

```bash
dreamscale train --dataset towel-fold --base pi0.5
```

Both are required. `towel-fold@1` trains version 1. From Hugging Face:
`--dataset hf://your-org/towel-fold`. Repeat `--dataset` to train on several Hugging Face
datasets together: they must match, with the same fps, state, action and cameras.

The CLI reads the dataset and shows the price and time. Say yes and it starts training and
shows progress on one line. Faulty episodes are dropped on our side before any GPU starts, free.
It ends with **Ready**. Ctrl-C stops watching, not training: `dreamscale train show tr_...`
picks it back up.

The default length suits your data. To set a budget instead, add `--max-usd 50`. To see the
price without starting anything, add `--quote`. `dreamscale train create --help` lists what else
you can set:
batch size, learning rate, warm-up, checkpoint spacing and held-out evaluation. To weight
episodes, or keep some frames' actions out of the loss, name a column with
`--sample-weight` or `--loss-mask`. To fine-tune FLUX.3 Action from Black Forest
Labs, use `--base flux-3-action-base`. Add `--rtc` too for real-time chunking
(experimental): its deployment then continues each chunk from the actions the robot
is still executing, so the arm doesn't jump where one chunk hands over to the next. To fine-tune
Xiaomi-Robotics-1 from Xiaomi, use `--base xiaomi-robotics-1`; it trains with real-time chunking
built in. A robot that is only a mobile base, such as a car, trains Xiaomi-Robotics-1 on its
velocities: add `--input mobile_base=base.json`, a file naming what your state and action hold, in
their order, such as `{"components": ["wz", "vx"]}` (`vx` forward speed, `vy` sideways speed, `wz`
yaw rate or steering). To fine-tune GR00T N1.7 from NVIDIA, use `--base gr00t-n1.7`.
To fine-tune Praxis-1 from Runway, use `--base praxis-1-base`. It takes any robot: 1 to 64 state
values and 1 to 64 action values (the two may differ), 1 to 3 cameras, recorded at 15, 30, 45 or
60 fps. It runs Runway's own recipe: of its settings, you can change only `--learning-rate`.
Add `--rtc` for real-time chunking (experimental). For a
private repo, run `dreamscale integrations hugging-face setup` once.

## 3. Deploy it

```bash
dreamscale train deploy tr_...
```

The build takes a few minutes and prints the command that runs it on your robot.
A FLUX.3 Action run on SO-101 or Bimanual YAM demos runs with
`dreamscale run so101 --deployment <name>` or `dreamscale run yam --deployment <name>`;
other FLUX.3 Action deployments run from
Python with `dreamscale.connect("flux-3-action-base", deployment="<name>")`.
A Xiaomi-Robotics-1 run on Bimanual YAM demos runs with `dreamscale run yam --deployment <name>`;
other robots connect from Python with `dreamscale.connect("xiaomi-robotics-1", deployment="<name>")`.
A mobile base sends the same state values as its dataset, in the same order, and each action
comes back in that order too. Between chunks it holds still (zero velocity), so a vehicle stops.
On a vehicle, execute the first 2–3 actions of each action chunk, then ask for the next.
A GR00T N1.7 run on SO-101 or Bimanual YAM demos runs with `dreamscale run so101 --deployment <name>`
or `dreamscale run yam --deployment <name>`; other robots connect from Python with
`dreamscale.connect("gr00t-n1.7", deployment="<name>")`.
A Praxis-1 deployment runs from Python on any robot, with
`dreamscale.connect("praxis-1-base", deployment="<name>")`. To start it on the
[lightning engine](/deployments#choose-its-engine), add `--engine lightning` to `train deploy`.
To rename it or keep it warm, see [Deployments](/deployments).

## Keep training a model

```bash
dreamscale train --dataset more-towels --base tr_...
```

It starts from that run's latest checkpoint (`--base-step 4500` for another one),
at a lower learning rate than a fresh run. The new dataset needs the same state
and action widths.

To continue a checkpoint you deployed, name the deployment:

```bash
dreamscale train --dataset more-towels --base towel-fold
```

A deployment made from a run starts from the checkpoint it serves. A checkpoint you
imported trains on its model's recipe: a π0.5 checkpoint (openpi or LeRobot) or a FLUX.3
Action export. Import one from Hugging Face or a folder with
`dreamscale deployments create` first. The quote checks the state and action widths,
and the run checks the rest (for FLUX.3 Action, the cameras and timing) before any GPU
time. Normalization is kept where your data agrees with the checkpoint's, and the
quote says which.

## Manage runs

```bash
dreamscale train list
dreamscale train stop tr_...     # you pay only for the steps it finished
dreamscale train resume tr_...   # within 30 days: the remaining steps, at the same rate
dreamscale train rm tr_...       # permanent; a running one is canceled first
```

The dashboard's Training page shows the same runs.
