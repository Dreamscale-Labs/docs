```text
dreamscale
├── login                     Sign in on this machine
├── doctor [core|so101|yam|sim|all]
├── models                    Models your organization can run
├── sim <benchmark>           Run a model in a local simulator
├── run so101 | yam           Run tasks on a robot
├── robots
│   ├── so101  setup | calibrate | home | release
│   └── yam    setup | home | release
├── sessions  list | stop
├── deployments  create | inspect | list | show | keep-warm | rm | restore
└── integrations
    ├── hud setup
    └── inspect-robots setup
```

Add `--help` to any command for the full list of options. `dreamscale --version`
also tells you when a newer release is out; upgrade with `uv tool upgrade dreamscale`.

## Account

| Command | What it does |
| --- | --- |
| `dreamscale login` | Opens the browser to sign in and saves a key to `~/.dreamscale/config.toml` |
| `dreamscale login --api-key KEY` | Saves an existing API key instead |
| `dreamscale doctor` | Checks Python, sign-in, and network |
| `dreamscale doctor so101` / `yam` / `sim` | Also checks that robot or the simulator. Add `--model` to check a specific model |
| `dreamscale models` | Lists the models your organization can run. `--verbose` shows each serving region and its state; `--json` prints JSON |

Every command also reads `DREAMSCALE_API_KEY`, which takes priority over the
saved login.

## run

`dreamscale run so101` and `dreamscale run yam` take the same options.

| Option | Default | What it does |
| --- | --- | --- |
| `--model` | required | Model to run. See `dreamscale models` |
| `--instruction` | prompt | Run this one task, then exit |
| `--max-actions` | until Ctrl+C | Stop each task after this many actions |
| `--keep-warm` | `300` | Seconds to keep the GPU reserved after each task (billed). `0` releases it |
| `--mode` | `async` | `async` replans while moving; `sync` runs each chunk to the end, then plans again |
| `--deployment` | none | Run your [deployment](/fine-tuning/deployments) (`ckpt_...`) |
| `--speed` | `standard` | `fast` uses a faster GPU at a higher rate, where the model offers it |
| `--region` | `available` | `available`, `nearest`, or `us-west-2` |
| `--max-joint-step` | 45° / 0.15 rad | Largest gap allowed between command and measured position |
| `--max-joint-velocity` | 150°/s / 1.0 rad/s | Joint speed cap. Also limits homing speed |
| `--effort` | `medium` | Language models only: `low`, `medium`, `high` (some models also `xhigh`, `max`) |
| `--max-cost` | none | Language models only: credit limit per task |
| `--hud`, `--hud-job NAME` | off | Record each task on [HUD](/integrations/hud) |
| `--inspect-robots` | off | Record an [Inspect Robots](/integrations/inspect-robots) eval log. With `--task`, `--epochs`, `--log-dir` |
| `--trace-dir PATH` | off | Save a local recording of each task. Add `--trace-images` to include camera frames |
| `--config PATH` | `~/.config/dreamscale/yam.json` | YAM only: rig config |

Joint limits are in degrees for SO-101 and radians for YAM.

## robots

| Command | What it does |
| --- | --- |
| `robots so101 setup` | Installs SO-101 support, then picks the port and both cameras |
| `robots so101 calibrate` | Guided calibration. Saves `~/.dreamscale/calibration/so101.json` |
| `robots so101 home` | Moves to the saved home pose, then releases the motors. `--set` saves the current pose as home |
| `robots so101 release` | Releases the motors. Support the arm first |
| `robots yam setup` | Installs YAM support, then maps cameras and CAN adapters in a browser page. `--cli` for the terminal |
| `robots yam home` | Moves both arms home, then releases the motors |
| `robots yam release` | Releases the motors. Support the arms first |

## sim

```bash
dreamscale sim libero --model molmoact2-libero --task-suite libero_spatial --task-id 0
```

| Option | What it does |
| --- | --- |
| `BENCHMARK` | `libero`, `robocasa365`, `molmospaces`, or `roboeval` |
| `--model` | A model for that benchmark. Run `dreamscale sim libero` without it to list them |
| `--task-suite`, `--task-id` | Which task to run |
| `--max-steps` / `--max-duration` | Episode budget in actions or seconds |
| `--keep-warm` | Same as `run`. Default `300` |
| `--non-interactive` | No viewer; print a JSON summary |
| `--output-root PATH` | Save the episode and timing to a folder |

## sessions

| Command | What it does |
| --- | --- |
| `sessions list` | Lists your open sessions. `--json` prints JSON |
| `sessions stop ID` | Ends one session and stops its billing |
| `sessions stop --all` | Ends all your open sessions |

## deployments

| Command | What it does |
| --- | --- |
| `deployments inspect REPO` | Shows the robot a Hugging Face repo declares and the datasets its statistics cover |
| `deployments create REPO` | Builds a deployment (about 15 minutes). See options below |
| `deployments list` | Lists your organization's deployments |
| `deployments show ID` | Shows one deployment, its build progress, or its error |
| `deployments keep-warm ID VALUE` | `off`, `10m`, `30m`, `1h`, `2h`, `6h`, `12h`, or `always`. `--take-over-from ID` moves Always from another deployment |
| `deployments rm ID` | Deletes a deployment. Owners only |
| `deployments restore ID` | Restores a deployment deleted in the last 7 days. Owners only |

`deployments create` options:

| Option | What it does |
| --- | --- |
| `--preset` | `so101`, `bimanual_yam`, or `custom`. Default: what the repo declares |
| `--region` | `us-west` (default) or `us-east` |
| `--camera key=view` | One camera, repeated in the order your robot sends them |
| `--image-size HxW` | Frame size, for example `360x640` |
| `--dataset` | Robot unit conversion: the dataset whose statistics to use |
| `--action-dim`, `--state-dim`, `--chunk`, `--hz`, `--context` | Custom robot shape |
| `--revision` | Branch, tag, or commit |
| `--hf-token` | Read token for a private repo. Defaults to `$HF_TOKEN`; never stored |
| `--no-wait` | Return once the build starts |

A custom robot needs at least `--camera`, `--image-size`, and `--dataset`.

## integrations

| Command | What it does |
| --- | --- |
| `integrations hud setup` | Installs HUD support and saves your HUD API key. See [HUD](/integrations/hud) |
| `integrations inspect-robots setup` | Installs Inspect Robots and registers `--policy dreamscale`. See [Inspect Robots](/integrations/inspect-robots) |
