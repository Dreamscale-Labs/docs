The public API of the `dreamscale` package, version `{{sdkVersion}}`. For a
walkthrough, start at [Python SDK](/python).

## What you need

- Python 3.11 or newer, and the package: `uv add dreamscale`.
- An account: sign in once with `uv run dreamscale login`, or set
  `DREAMSCALE_API_KEY`.

## dreamscale.connect()

Connect to a model and return a [`Policy`](#policy). It returns once a server is
ready. If every server is busy, it waits in a queue and shows your position.

```python dreamscale.connect
def connect(
    model: str,
    *,
    deployment: str | None = None,
    api_key: str | None = None,
    on_progress: Callable[[str], None] | None = ...,
    region: str = "nearest",
    speed: str | None = None,
    rtc: str | None = "auto",
    provider: str | None = None,
    transport: str = "auto",
    startup_timeout: float | None = None,
) -> Policy: ...
```

| Parameter | Default | Description |
| --- | --- | --- |
| `model` | required | A model from [Models](/models) (or `dreamscale models list`), or one of your deployments as `<account>/<slug>` or its bare slug. |
| `deployment` | `None` | Run this deployment (its name or `ckpt_…` ID) on `model`, its base model. Usually you pass the deployment as `model` instead. |
| `api_key` | `None` | API key to use. Without it: `DREAMSCALE_API_KEY`, then your `dreamscale login`. |
| `on_progress` | stderr or logger | Called with each progress line (queue position, startup). The default prints to stderr on a terminal, otherwise logs to the `dreamscale` logger. `None` silences it. |
| `region` | `"nearest"` | `"nearest"` (lowest latency from you), `"available"` (any region with a warm server first), or an exact region such as `"us-west-2"`. |
| `speed` | `None` (standard) | `"standard"` or `"fast"`, where the model supports it. |
| `rtc` | `"auto"` | Real-time chunking: `"auto"` (the model's default), `"on"`, `"off"`, `"train_time"` or `"inference_time"`. A deployment keeps its own setting ([`dreamscale deployments rtc`](/reference/cli#dreamscale-deployments-rtc)). |
| `provider` | `None` | Advanced: require `"aws"` or `"modal"`. |
| `transport` | `"auto"` | `"auto"` (QUIC, then relay), `"quic"` or `"relay"`. |
| `startup_timeout` | `None` | Most seconds to wait for a server. `None` follows the server's budget, which grows while a training run makes room for your robot. |

Raises [`AuthError`](#errors), [`CreditsError`](#errors) or
[`NoCapacityError`](#errors) when it can't connect.

```python
import dreamscale

policy = dreamscale.connect("pi0.5-so101")
side, wrist = ..., ...  # H×W×3 uint8 RGB frames
joints = ...  # 6 values: LeRobot degrees, gripper 0–100
observation = dreamscale.so101.observation(
    side_frame=side, wrist_frame=wrist, joint_positions=joints,
)
chunk = policy.predict(observation, instruction="pick up the red block")
print(len(chunk.actions), "x", len(chunk.actions[0]))
policy.close()
```

It prints `30 x 6`.

## dreamscale.aconnect()

The same as [`connect()`](#dreamscale-connect), awaited, for async code. It
takes the same parameters and returns an [`AsyncPolicy`](#asyncpolicy).

```python dreamscale.aconnect
async def aconnect(
    model: str,
    *,
    deployment: str | None = None,
    api_key: str | None = None,
    on_progress: Callable[[str], None] | None = ...,
) -> AsyncPolicy: ...
```

```python
import asyncio

import numpy as np

import dreamscale


async def main():
    policy = await dreamscale.aconnect("pi0.5-libero")
    async with policy:
        frame = np.zeros((256, 256, 3), dtype=np.uint8)
        observation = dreamscale.libero.observation(
            agent_frame=frame, wrist_frame=frame, state=[0.0] * 8,
        )
        chunk = await policy.predict(observation, instruction="pick up the black bowl")
        print(len(chunk.actions), "x", len(chunk.actions[0]))


asyncio.run(main())
```

## Policy

What `connect()` returns: one connection to a model. If the connection drops,
the next call reconnects. After a minute with nothing in flight, it frees the
server, and the next call reconnects. It closes when your program exits.

Use it as a context manager to close it when the block ends:

```python
import dreamscale

with dreamscale.connect("pi0.5-libero") as policy:
    print(policy.model, policy.state)
```

| Property | Type | Description |
| --- | --- | --- |
| `model` | `str` | The model's name, as you passed it to `connect()`. |
| `state` | `str` | `"opening"`, `"queued"`, `"ready"`, `"released"` (server freed; the next call reconnects), `"reconnecting"` or `"closed"`. |
| `contract` | `PolicyContract` | What the model returns and accepts. See [`Policy.contract`](#policy-contract). |

### Policy.predict()

Send one observation and get back one [action chunk](#action-chunk): the model's
next actions. It doesn't move the robot.

```python dreamscale.Policy.predict
def predict(
    observation,
    instruction: str | None = None,
    *,
    timeout_s: float = 60.0,
    past_observations: Sequence[Observation] | None = None,
    action_history: Sequence[Sequence[float]] | None = None,
    committed_actions: Sequence[Sequence[float]] | None = None,
) -> ActionChunk: ...
```

| Parameter | Default | Description |
| --- | --- | --- |
| `observation` | required | An observation from the robot's helper, for example [`dreamscale.so101.observation()`](#dreamscale-so101-observation). |
| `instruction` | required | The task in plain words, for example `"pick up the red block"`. It must not be empty. |
| `timeout_s` | `60.0` | Most seconds to wait for the chunk. Raises `Error` with code `action_timeout` after it. |
| `past_observations` | `None` | The observations of the control ticks just before this one, oldest first, from the same helper: as many as `policy.contract.past_observations`. Models that read recent frames and states need them, FLUX.3 Action deployments among them. See [History the model reads](#history-the-model-reads). |
| `action_history` | `None` | The actions your robot executed on those ticks, oldest first: as many as `policy.contract.action_history`. `next_action()` keeps both for you. |
| `committed_actions` | `None` | The actions your robot will still execute after this observation, in order, in the same units as `actions`. The new chunk starts with as many as the server expects to play before it arrives. Needs `policy.contract.rtc == "train_time"`, or `"inference_time"` on a deployment. See [Running chunks on your own clock](#running-chunks-on-your-own-clock). |

Raises [`ObservationError`](#errors) before sending if the observation, its
history or the committed actions don't match the model, and `Error` with code
`history_required` if you leave out history the model can't run without.

#### Running chunks on your own clock

`predict()` returns one chunk and leaves running it to you.
([`next_action()`](#policy-next_action) does it for you: buffering, early
requests, blending.)

**What the server does.** With `committed_actions` and `policy.contract.rtc`
`"train_time"`, the server estimates how many of them your robot will execute
before the new chunk reaches this computer. It counts from `capture_time_ns`
through upload, queueing, inference and the trip back, measured on your
session's recent requests. It pins that many (`prefix_rows`: at most
`policy.contract.max_prefix_rows`, and at most the rows you sent), returns them
exactly as you sent them, and generates the rest to follow on. On a deployment
with `"inference_time"`, it guides the start of the new chunk toward them over
the same count instead: close to what you sent, not exact. Without
`committed_actions`, each chunk starts fresh.

**What you do.**

- **Rows and time.** Row 0 is the first action to execute after
  `chunk.capture_time_ns`; row `i` follows `i / policy.contract.action_hz`
  seconds later. Times are this computer's `time.time_ns()`: convert them if
  your robot stamps frames on another clock.
- **Request early.** Send the next request while the current chunk still has at
  least `ceil(latency × action_hz) + 1` actions left, where latency is capture
  to receipt, measured on your own chunks.
- **Commit what will run.** Pass the actions your robot will execute after the
  new observation, after any limits your controller applies. Rows past what the
  server can pin are ignored. After a reconnect, keep passing them.
- **Switch.** When the chunk arrives, switch at the row due now:
  `floor((now − capture_time_ns) × action_hz)`.


**Checking it works.** Compare the row you switch at with `prefix_rows`:

- **At or below `prefix_rows`:** smooth. The pinned rows match what was playing.
- **Above `prefix_rows`:** the chunk arrived later than estimated, and the robot
  jumps at the switch. The estimate ends when the chunk reaches this computer,
  so a delay before your controller switches isn't in it. Switch sooner after
  arrival, or request earlier.
- **Equal to the rows you sent:** you capped it. Send more.
- **Equal to `max_prefix_rows` on most chunks:** latency takes most of each
  chunk, leaving few new actions. Request earlier, or cut latency.
- **0:** you sent no rows, because the chunk ran out first. Request earlier.

**Handing over to another deployment.** Request its first chunk the same way, early,
while the current chunk still has the latency's worth of actions left, then switch
at the row due now:

```python
import dreamscale

pick = dreamscale.connect("pi0.5-so101")
place = dreamscale.connect("pi0.5-so101")
side, wrist = ..., ...  # H×W×3 uint8 RGB frames
joints = ...  # 6 values: LeRobot degrees, gripper 0–100
observation = dreamscale.so101.observation(
    side_frame=side, wrist_frame=wrist, joint_positions=joints,
)
chunk = pick.predict(observation, "pick up the red block")
# ... execute chunk; with the latency's worth of actions left, ask the next one:
handover = place.predict(observation, "put it in the bowl")
print(len(chunk.actions), len(handover.actions))
pick.close()
place.close()
```

#### History the model reads

Some models read the ticks before the observation as well, FLUX.3 Action among
them. `policy.contract.past_observations` and `policy.contract.action_history`
say how many to pass; both are 0 for models that don't.

```text
ticks:    … t-2   t-1 │  t    t+1  …
                      │  ▲ observation
past_observations ──► │            oldest first, ending at t-1
action_history ─────► │            executed, oldest first
                      │ ◄── committed_actions, chunk rows (row 0 = t)
```

- **Keep the last ticks.** On every control tick, at `action_hz`, keep the
  observation and the action you sent. Pass the most recent as
  `past_observations` and `action_history`; extra ones are ignored.
- **Episode start.** Pass `[]` or fewer: the SDK pads them as the model was
  trained, and `chunk.history_padded` says how many ticks it filled in. Once
  the episode is a few ticks in, it should be 0.
- **No gaps.** With capture times, the entries must be one control tick apart,
  up to the observation. A gap raises `ObservationError` before sending.

<Warning>
  The robot will move. Enforce joint, speed and workspace limits locally, and
  keep a physical e-stop within reach. Cloud inference does not replace your
  robot's safety controller.
</Warning>

```python
import math
import time
from collections import deque
from concurrent.futures import ThreadPoolExecutor

import dreamscale

policy = dreamscale.connect("ckpt_...")  # your deployment
c = policy.contract
pool = ThreadPoolExecutor(1)
task = "fold the towel"
rtc = c.rtc == "train_time"  # pins committed actions
ticks, done = deque(maxlen=64), deque(maxlen=64)


def observe():
    # Your robot's code: read the frames and state.
    top, left_wrist = ..., ...  # H×W×3 uint8 RGB frames
    left_joints, left_gripper = ..., ...  # checkpoint units
    return dreamscale.robot.observation(
        cameras={"base": top, "left_wrist": left_wrist},
        state=[*left_joints, left_gripper],
        capture_time_ns=time.time_ns(),
    )


def send_to_robot(action):
    # Your robot's code: apply one action.
    ...


def last(items, n):  # the n most recent, oldest first
    return list(items)[len(items) - n:]


def request(obs, rest):
    return pool.submit(
        policy.predict, obs, task,
        past_observations=last(ticks, c.past_observations),
        action_history=last(done, c.action_history),
        committed_actions=rest if rtc else None,
    )


def age_s(chunk):  # since its observation was captured
    return (time.time_ns() - chunk.capture_time_ns) / 1e9


chunk, pending, latency_s = None, None, 0.0
while True:
    obs = observe()
    row = int(age_s(chunk) * c.action_hz) if chunk else 0
    left = len(chunk.actions) - row if chunk else 0
    lead = math.ceil(latency_s * c.action_hz) + 1
    if pending is None and left <= lead:
        rest = chunk.actions[row:] if chunk else []
        pending = request(obs, rest)
    if pending is not None and pending.done():
        chunk, pending = pending.result(), None
        latency_s = age_s(chunk)
        row = int(latency_s * c.action_hz)
        print(f"row {row}: pinned {chunk.prefix_rows}, "
              f"padded {chunk.history_padded}")
    if chunk and row < len(chunk.actions):
        action = chunk.actions[row]
    else:
        action = obs.state  # the chunk ran out: hold still
    send_to_robot(action)
    ticks.append(obs)
    done.append(action)
    time.sleep(1 / c.action_hz)
```

### Policy.next_action()

Get one action to execute now. Call it once per control tick: it returns on the
model's clock, within one tick. It blends chunks so motion stays smooth, and
while no model action is ready (the first chunk, or a reconnect), an arm gets
its measured position back so it holds still.

```python dreamscale.Policy.next_action
def next_action(
    observation,
    instruction: str | None = None,
    *,
    pace: bool = True,
    timeout_s: float | None = None,
) -> tuple[float, ...]: ...
```

| Parameter | Default | Description |
| --- | --- | --- |
| `observation` | required | This tick's observation from the robot's helper. |
| `instruction` | required | The task in plain words. Pass a new one to switch tasks: the robot keeps moving, and the new task takes over within about two round trips (the chunk already on its way may play first). |
| `pace` | `True` | Return at the model's control rate. A late call gets the next action at once, and the actions it missed are skipped. `False` returns as soon as an action is ready. |
| `timeout_s` | `None` (60 s) | For the LIBERO simulator, which waits for a real action instead of holding: most seconds to wait. |

Returns one action: absolute joint targets for a robot arm, in the same order
and units as its observation (see [Models](/models)). With real-time chunking
(`policy.contract.rtc` is `"train_time"`), each request carries the actions still
to execute, so chunks join without a jump; there is nothing to pass.

```python
import dreamscale

policy = dreamscale.connect("pi0.5-so101")
side, wrist = ..., ...  # H×W×3 uint8 RGB frames
joints = ...  # 6 values: LeRobot degrees, gripper 0–100
observation = dreamscale.so101.observation(
    side_frame=side, wrist_frame=wrist, joint_positions=joints,
)
action = policy.next_action(observation, instruction="pick up the red block")
print(len(action))
policy.close()
```

### Policy.prefetch()

Request a policy's first chunk ahead of handing the robot over to it, so its first
`next_action()` doesn't hold. Call it about one round trip before the switch, with
the same instruction; it returns without waiting for the chunk.

```python dreamscale.Policy.prefetch
def prefetch(
    observation,
    instruction: str | None = None,
    *,
    timeout_s: float = 60.0,
) -> None: ...
```

| Parameter | Default | Description |
| --- | --- | --- |
| `observation` | required | This tick's observation from the robot's helper. |
| `instruction` | required | The task the next policy runs. |
| `timeout_s` | `60.0` | Most seconds to wait for its session to open. |

```python
import dreamscale

pick = dreamscale.connect("pi0.5-so101")
place = dreamscale.connect("pi0.5-so101")
side, wrist = ..., ...  # H×W×3 uint8 RGB frames
joints = ...  # 6 values: LeRobot degrees, gripper 0–100
observation = dreamscale.so101.observation(
    side_frame=side, wrist_frame=wrist, joint_positions=joints,
)
pick.next_action(observation, instruction="pick up the red block")
place.prefetch(observation, instruction="put it in the bowl")
action = place.next_action(observation, instruction="put it in the bowl")
pick.close()
place.close()
```

### Policy.contract

What the connected model returns and accepts. Read-only.

| Field | Type | Description |
| --- | --- | --- |
| `action_hz` | `float` | The rate a chunk's actions are spaced at. |
| `chunk_size` | `int` | Actions per chunk. |
| `action_dim` | `int` or `None` | Values per action. |
| `state_dim` | `int` or `None` | Values in a deployment's state. |
| `camera_keys` | `tuple[str, ...]` | A deployment's camera keys, in order. Empty where the robot's helper names the cameras. |
| `rtc` | `str` | Real-time chunking: `"train_time"`, `"inference_time"` or `"off"`. `committed_actions` needs `"train_time"`, or `"inference_time"` on a deployment. |
| `max_prefix_rows` | `int` or `None` | The most committed actions a chunk can start with: 0 unless `rtc` is `"train_time"`, `None` when the server doesn't report it. |
| `past_observations` | `int` | How many `past_observations` `predict()` takes: the ticks just before the observation. 0 for models that don't read them. |
| `action_history` | `int` | How many executed actions `predict()` takes as `action_history`. 0 for models that don't read them. |

## AsyncPolicy

What `aconnect()` returns. It has the same properties as [`Policy`](#policy),
and the same methods, awaited: `await policy.predict(...)`,
`await policy.next_action(...)` and `await policy.close()`. Use
`async with policy:` to close it when the block ends.

```python dreamscale.AsyncPolicy.predict
    timeout_s: float = 60.0,
    past_observations: Sequence[Observation] | None = None,
    action_history: Sequence[Sequence[float]] | None = None,
    committed_actions: Sequence[Sequence[float]] | None = None,

```

```python dreamscale.AsyncPolicy.next_action

```

## Action chunk

What `predict()` returns.

| Field | Type | Description |
| --- | --- | --- |
| `actions` | `tuple[tuple[float, ...], ...]` | The chunk: one row per action, in order. Its size is on [Models](/models), for example 30 × 6 for `pi0.5-so101`. |
| `capture_time_ns` | `int` | When the observation was captured (`time.time_ns()`). Row 0 is the first action to execute after it; row `i` follows `i / policy.contract.action_hz` seconds later. |
| `prefix_rows` | `int` | How many of your `committed_actions` start this chunk: exactly as you sent them, or guided toward them on a deployment with `"inference_time"`. 0 without them. |
| `history_padded` | `int` | How many ticks of history the SDK filled in (an episode's start, or history you didn't pass). 0 for a complete history, and for models that don't read one. |
| `observation_id` | `int` | Which observation this chunk answers. |
| `chunk_id` | `int` or `None` | The server's ID for this chunk. |
| `timing.obs_to_action_ms` | `float` | Milliseconds from sending the observation to receiving the chunk. |
| `timing.server_total_ms` | `float` or `None` | Milliseconds the server spent on the request. |
| `transport_mode` | `str` or `None` | How it arrived: `"quic"`, `"relay"`, `"quic_punch"` (direct QUIC to a Modal worker) or `"wss_tunnel"` (its WebSocket). A Modal session moves between the last two on its own: if the direct path drops, it continues on the WebSocket within about a second and returns to QUIC when the path is back (SDK 0.1.0a205+). |

## Observation helpers

Each robot type has one helper, shared by every model on that robot. It checks
the values before anything is sent and raises [`ObservationError`](#errors)
naming any wrong field. Frames are H×W×3 `uint8` RGB at any size: the SDK
resizes them for the model.

### dreamscale.so101.observation()

```python dreamscale.so101.observation

    *,
    side_frame: np.ndarray,
    wrist_frame: np.ndarray,
    joint_positions: Sequence[float],
    capture_time_ns: int | None = None,
) -> So101Observation: ...
```

| Parameter | Description |
| --- | --- |
| `side_frame` | The fixed side camera. |
| `wrist_frame` | The wrist camera. |
| `joint_positions` | 6 values in calibrated LeRobot degrees: `shoulder_pan`, `shoulder_lift`, `elbow_flex`, `wrist_flex`, `wrist_roll`, then `gripper` (0–100). |
| `capture_time_ns` | When the frames and state were captured, as this computer's `time.time_ns()`. Default: when the request is built. Pass it when the frames are older than the call. |

### dreamscale.robot.observation()

Any robot: named cameras and one state vector, for a deployment shaped to your
robot. The deployment sets the camera keys, their order and the state width.
Send values in the units the checkpoint was trained on; actions come back the
same way. The deployment's dashboard page shows its keys and loop.

```python dreamscale.robot.observation
def observation(
    *,
    cameras: Mapping[str, np.ndarray],
    state: Sequence[float],
    capture_time_ns: int | None = None,
) -> RobotObservation: ...
```

| Parameter | Description |
| --- | --- |
| `cameras` | Frames keyed by the deployment's camera keys, in its order. |
| `state` | The state vector: joint positions and grippers, in the checkpoint's units. |
| `capture_time_ns` | When the frames and state were captured, as this computer's `time.time_ns()`. Default: when the request is built. Pass it when the frames are older than the call. |

```python
import dreamscale

top, left_wrist = ..., ...  # H×W×3 uint8 RGB frames
left_joints, left_gripper = ..., ...  # in the checkpoint's units
observation = dreamscale.robot.observation(

)
```

## dreamscale.datasets

## dreamscale.trainings

Fine-tune a base model on your LeRobot dataset, on Dreamscale's GPUs, from
Python. It is `dreamscale train` without the prompt: the price is quoted
first, and `max_usd` is the most a run may cost. See [Training](/training).

```python
import dreamscale

ds = dreamscale.datasets.upload("./towel-fold")
run = dreamscale.trainings.create(dataset=ds, base="pi0.5", max_usd=50)
run.wait()  # a live status line until it finishes
deployment = run.deploy()
policy = dreamscale.connect(deployment["model"], deployment=deployment["id"])
```

### dreamscale.trainings.create()

Start a training run without a prompt. It refuses to start if the quote is
above `max_usd`. Starting the same dataset with the same settings while that run
is still going returns that run instead of a new one.

```python dreamscale.trainings.create
def create(
    *,
    dataset: Dataset | str,
    base: str,
    max_usd: float | str | Decimal,
    steps: int | None = None,
    rtc: bool | None = None,
    name: str | None = None,
    hf_token: str | None = None,
) -> Training: ...
```

| Parameter | Default | Description |
| --- | --- | --- |
| `dataset` | required | A [`Dataset`](#dreamscale-datasets), a name (`"towels"`, `"towels@2"`, `"acme/towels"`), or a Hugging Face repo as `hf://owner/name` (optionally `@revision`). |
| `base` | required | Base model: the same values as `--base` on [`dreamscale train`](/reference/cli#dreamscale-train). |
| `max_usd` | required | The most this run may cost, in US dollars. |
| `steps` | `None` (auto) | Training length in steps. |
| `rtc` | `None` (the base's) | Train with (`True`) or without (`False`) real-time chunking. `None` trains what the base does: on for π0.5, off for FLUX.3 Action, where it is experimental. |
| `name` | `None` (the dataset) | Display name. |
| `hf_token` | `None` | Hugging Face token for a private repo. Default: `HF_TOKEN`, else your connected token. |

### dreamscale.trainings.get()

```python dreamscale.trainings.get
def get(run_id: str) -> Training: ...
```

Get a training run by its `tr_…` ID.

### Training

A training run.

| Member | Description |
| --- | --- |
| `id` | Its `tr_…` ID. |
| `status` | `"queued"`, `"preparing"`, `"training"`, `"stopped"`, `"ready"`, `"failed"` or `"canceled"`. |
| `checkpoints` | Its saved checkpoints, as a list of dicts with their `step`. |
| `data` | The run as a dict, as of the last refresh. |
| `refresh()` | Fetch the latest state; returns the run. |
| `wait(quiet=False)` | Follow it until it finishes, with a live status line unless `quiet`. Raises its error if it failed. Ctrl+C stops waiting, not training. |
| `stop()` | Stop it. Nothing is charged before training starts; after, you pay for the completed steps, and it saves a checkpoint. |
| `resume(max_usd)` | Continue a stopped run within 30 days for its remaining steps. Refuses a price above `max_usd`. |
| `delete()` | Delete it for good. One still going is canceled first. Deployments made from it keep running. |
| `deploy(step=None, region="us-west")` | Deploy a checkpoint (default the latest) in `"us-west"` or `"us-east"`. Returns the deployment as a dict: pass its `model` and `id` to `connect()`. |

## Errors

Every SDK error is a `dreamscale.Error`. Each names the problem and the next
step, so printing it is usually enough.

| Class | Raised when |
| --- | --- |
| `dreamscale.Error` | The base of every SDK error. |
| `dreamscale.AuthError` | Not signed in, or the API key was rejected. |
| `dreamscale.CreditsError` | Your organization is out of credits. |
| `dreamscale.NoCapacityError` | Your organization already runs 2 robots on shared models (code `shared_session_limit`), or the line for a server is full. While servers are only busy, a robot waits in line and is told its position instead. |
| `dreamscale.ObservationError` | An observation or instruction doesn't match the model. Raised before anything is sent. Also a `ValueError` and a `TypeError`. |

| Member | Description |
| --- | --- |
| `code` | The problem as a short ID, for example `action_timeout` or `history_required`. |
| `fix` | The next step, in words. |
| `render()` | The problem, its cause and the fix, as printed by the CLI. |

```python
import dreamscale

try:
    policy = dreamscale.connect("pi0.5-libero")
except dreamscale.NoCapacityError as error:
    print(error.code, error.fix)
```
