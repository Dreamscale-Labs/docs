A deployment serves your own fine-tune, shaped to your robot, in one region. A
server starts when a robot connects and stops when it disconnects, unless you keep
it warm.

## What you need

- The latest CLI: `uv tool upgrade dreamscale`.
- Credits on your account: each build runs a short check on a server.
- A π0.5 checkpoint: an openpi checkpoint (`params/` with `assets/<id>/norm_stats.json`)
  or a LeRobot export (`config.json`, `model.safetensors` and the saved processors),
  up to 24 GB. It can be on Hugging Face or in a local folder.

## 1. Create it

From Hugging Face (any `huggingface.co` link works, including a checkpoint
folder's page):

```bash
dreamscale deployments inspect hf://your-org/towel-fold --base pi0.5
dreamscale deployments create hf://your-org/towel-fold --base pi0.5 --preset bimanual_yam --slug towel-fold
```

From a local folder:

```bash
dreamscale deployments create ./checkpoints/6000 --preset bimanual_yam --slug towel-fold
```

`inspect` shows what the checkpoint declares (format, cameras, widths, horizon,
rate, RTC) and where each value came from; flags on `create` override any of
them. A folder's configuration files are read first and only the files the build
needs are uploaded, never `train_state/` or code. Running the same command again
uploads nothing new, and an interrupted upload resumes. Uploads are kept for 30
days.

The build takes a few minutes and ends with **Ready**. For a private repo, run
`dreamscale integrations hugging-face setup` once to save a read-only token.

## 2. Run it

After the robot's setup ([Bimanual YAM](/robots/yam) or [SO-101](/robots/so101)):

```bash
dreamscale run yam --deployment towel-fold --instruction "fold the towel"
```

From Python:

```python
policy = dreamscale.connect("pi0.5", deployment="towel-fold")
```

The slug (`towel-fold`) and the `ckpt_...` ID both work everywhere. The
deployment's page on the dashboard has the full loop for your robot. The first
connection starts a server, usually in under a minute.

## 3. Keep it warm (optional)

```bash
dreamscale deployments keep-warm towel-fold 30m
dreamscale deployments stop towel-fold   # stop its server now
```

Keep-warm holds a server ready between runs (`10m` to `12h`, or `always`) and is
billed like connected time. Off, the default, stops the server when the session
ends. `stop` ends the server now, and a connected robot reconnects to a new one on
its next call; with `always`, `restart` does the same and starts a fresh one.

## Delete it

```bash
dreamscale deployments rm towel-fold
```

Deleting is permanent and can't be undone: running sessions end and the slug is
free again. Only organization owners can delete. Usage history stays.
