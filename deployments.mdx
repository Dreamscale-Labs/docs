A deployment serves your own fine-tune, shaped to your robot, in one region. A
server starts when a robot connects and stops when it disconnects, unless you keep
it warm.

## What you need

- The latest CLI: `uv tool upgrade dreamscale`.
- Credits on your account: each build runs a short check on a server.
- A π0.5 checkpoint: an openpi checkpoint (`params/` with `assets/<id>/norm_stats.json`)
  or a LeRobot export (`config.json`, `model.safetensors` and the saved processors),
  up to 24 GB. It can be on Hugging Face or in a local folder.

## 1. Create it

From Hugging Face (any `huggingface.co` link works, including a checkpoint
folder's page):

```bash
dreamscale deployments inspect hf://your-org/towel-fold --base pi0.5
dreamscale deployments create hf://your-org/towel-fold --base pi0.5 --preset bimanual_yam --slug towel-fold
```

From a local folder:

```bash
dreamscale deployments create ./checkpoints/6000 --preset bimanual_yam --slug towel-fold
```

`inspect` shows what the checkpoint declares (format, cameras, widths, horizon,
rate, RTC) and where each value came from; flags on `create` override any of
them. A folder's configuration files are read first and only the files the build
needs are uploaded, never `train_state/` or code. Running the same command again
uploads nothing new, and an interrupted upload resumes. Uploads are kept for 30
days.

The build takes a few minutes and ends with **Ready**. A script can wait for it:
`dreamscale deployments show towel-fold --json` reports `"status": "ready"`. For a private repo, run
`dreamscale integrations hugging-face setup` once to save a read-only token.

## 2. Run it

After the robot's setup ([Bimanual YAM](/robots/yam) or [SO-101](/robots/so101)):

```bash
dreamscale run yam --model acme-robotics/towel-fold --instruction "fold the towel"
```

From Python:

```python
policy = dreamscale.connect("acme-robotics/towel-fold")
```

A checkpoint whose actions aren't joint targets (its state and action widths
differ, e.g. end-effector deltas) runs from Python only, and while reconnecting
the robot waits for the next action instead of holding still.

A deployment's name is `<account>/<slug>`: your account (shown in Settings) and
the slug you gave it. Its bare slug (`towel-fold`) and its `ckpt_...` ID work
everywhere too. To rename it: `dreamscale deployments rename towel-fold folding-v2`.
The old name keeps working until another of your deployments takes it. The
deployment's page on the dashboard has the full loop for your robot. The first
connection starts a server, usually in under a minute.

If your region is full, we start your server in the next-closest region (US West
and US East are about 60–70 ms apart), and the CLI and SDK say so while it starts.
It's on by default. To keep a deployment in its own region, so a robot waits there
instead, turn it off: `dreamscale deployments fallback towel-fold off`, or
`--no-region-fallback` on `create` and `train deploy`, or the Region card on its page.

## 3. Keep it warm (optional)

```bash
dreamscale deployments keep-warm towel-fold 30m
dreamscale deployments stop towel-fold   # stop its server now
```

Keep-warm holds a server ready between runs (`10m` to `12h`, or `always`) and is
billed like connected time. Off, the default, stops the server when the session
ends. `stop` ends the server now, and a connected robot reconnects to a new one on
its next call; with `always`, `restart` does the same and starts a fresh one.

To warm it up before your robot needs it, add `--now`: it starts the server and
waits until it is ready. `dreamscale deployments show towel-fold` and the
deployment's page say what it is doing: **Ready**, **Starting**, or **Waiting for a
GPU** while the cloud allocates one. An idle policy on a deployment kept warm stays
connected for the keep-warm (with `always`, until you close it).

If the server stops under a running robot (rare), the robot holds still while a
new one starts, usually under a minute. To cut that pause to a few seconds, keep a
spare ready on a deployment that autoscales:

```bash
dreamscale deployments keep-warm towel-fold 1h --robots 2
```

A second server stays warm, and if yours stops, the robot moves to it in about 5
seconds. It's billed as two robots while kept warm.

## Delete it

```bash
dreamscale deployments rm towel-fold
```

It asks first (in a script, pass `--yes`). Deleting is permanent and can't be undone:
running sessions end and the slug is free again. Only organization owners can delete. Usage history stays.
