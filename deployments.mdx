A deployment serves your own fine-tune from Hugging Face, shaped to your robot.
Without a deployment, `--model perceptron-isaac05-yam` runs the Isaac 0.5 base
weights.

## What you need

- Isaac 0.5 enabled for your organization. Email
  [{{supportEmail}}](mailto:{{supportEmail}}) to request it.
- SDK and CLI {{sdkVersion}} or newer: `uv tool upgrade dreamscale`.
- A Hugging Face repo with your full Isaac 0.5 fine-tune. For a private repo, set
  `HF_TOKEN`.

The repo holds the full Hugging Face export, F32, BF16 or F16, up to 160 GB.
LoRA adapters and single-file checkpoints aren't supported.

```text
your-org/isaac-finetune
├── config.json                      Isaac 0.5 architecture
├── model.safetensors.index.json
├── model-00001-of-00004.safetensors
├── …
├── policy_normalization.json        recommended: your normalization statistics
└── isaac_deployment_adapter.json    optional: your robot's shape
```

`policy_normalization.json` converts the model's outputs into your robot's
units. Ship the statistics from your own training data; without them, the
deployment uses the base model's.

## 1. Create it

```bash
dreamscale deployments inspect hf://your-org/isaac-finetune
dreamscale deployments create hf://your-org/isaac-finetune --preset bimanual_yam --name my-finetune
```

`inspect` checks the repo's files and lists the robot unit conversions it
carries. Without `--preset`, `create` uses the robot your repo's adapter
declares. The first build takes about 15 minutes. `dreamscale deployments list`
then shows it as **Ready** with an ID like `ckpt_...`. You can also create one
on the [Deployments](https://app.dreamscalelabs.com/dashboard/deployments) page:
choose **Detect** first, then check the robot and its unit conversion.

## 2. Run it

After the robot's setup ([Bimanual YAM](/robots/yam) or [SO-101](/robots/so101)):

```bash
dreamscale run yam --model perceptron-isaac05-yam --deployment ckpt_... --instruction "pick up the cube"
```

From Python:

```python
policy = dreamscale.connect("perceptron-isaac05", checkpoint="ckpt_...")
```

Build observations with `dreamscale.robot.observe`, using the camera keys and
state width shown on the deployment's page; its **Connect** card has the full
loop. The first action of each new instruction takes a few seconds while the
task is prepared.

A session runs a deployment only when it names it. Without `--deployment`
(or `checkpoint=`), it runs the base weights.

## 3. Keep it warm (optional)

A cold start takes 2–3 minutes. Keep-warm keeps a GPU ready between runs, and
is billed like connected time. Off (the default) stops the GPU when the session
ends.

```bash
dreamscale deployments keep-warm ckpt_... 30m
```

## Replace a fine-tune

A new fine-tune is a new deployment with a new ID. Create it, then move
Always-on to it and update the ID in your code:

```bash
dreamscale deployments keep-warm ckpt_new always --take-over-from ckpt_old
dreamscale deployments rename ckpt_new "<new name>"
```
